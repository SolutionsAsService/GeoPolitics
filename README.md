# GeoPolitics

A data set of international organisations, defence agreements, languages, religions and tax havens, and **the Weave**.
The Weave is a site built from that data. It draws each organisation, shared language or games series as one thread
through its member countries on a world map.

Live address once deployed: `https://geopolitics.shadw.app/`

## What is in the data

Everything is in [`data/`](data/). It has 27 JSON files, and all of them parse. Seven did not until 31 Oct 2026, and
each repair is listed on the site's Data page and in [`data/sources/repairs.md`](data/sources/repairs.md).

| File or folder | What it holds |
|---|---|
| `AfricanOrgs.json`, `AmericanOrgs.json`, `AsianOrgs.json`, `EuropeanOrgs.json` | Regional organisations |
| `TransatlanticOrgs.json`, `TranscontinentOrgs.json` | Organisations that span continents |
| `CountryBlocks.json`, `ArmsControlOrgs.json`, `nuclear_power_orgs.json` | Alliances, arms control and nuclear bodies |
| `TradeBlocks.json`, `TaxHavens.json` | Trade blocs, and a list of places the data calls tax havens |
| `IdealogicalOrgs.json`, `CulturalEthnicReligousOrgs.json`, `EducationalOrgs.json` | Political, cultural and educational groupings |
| `DefunctOrgs.json` | Organisations that no longer exist |
| `DefenseAgreements/UKDefense.json` | The United Kingdom's defence agreements |
| `Languages/`, `Religion/` | Profiles of seven languages and two religions |
| `US/` | US presidents, and one example record of a US Army special-forces team |
| `sources/` | What the site adds, each with its source. Wikidata query results (CC0) are stored with their queries and fetch times. Country shapes come from Natural Earth via world-atlas 2.0.2. |

Each organisation is an object with `name`, often `abbreviation`, `type` and `purpose`, and a `members` field. The
`members` field is either a list of countries or, in 86 records, a sentence such as "27 European countries".

## The site

The site is in [`site/`](site/), generated by [`_src/build.mjs`](_src/build.mjs). The build has no dependencies.

```bash
node _src/build.mjs
```

```bash
node _src/measure.mjs --selftest
```

```bash
node _src/measure.mjs
```

The first command builds the site from the data. The second checks that every measuring probe catches a page built to
fail it. The third renders every page in headless Chrome and checks the first screen, overflow, contrast, target sizes
and page weight.

To refresh the Wikidata snapshots:

```bash
python _src/fetch_wikidata.py data/sources/wikidata
```

How the build treats the data:

- Every member name is resolved to an ISO 3166 code using Wikidata's names and aliases plus a small alias table, which
  the site lists.
- A name that resolves to no place is listed on the Data page, never guessed.
- When a record gives its members as a sentence, the build fills them from Wikidata's member-of statements only if
  Wikidata's count agrees with the count the sentence states.
- When the data lists the same organisation twice, it is drawn once.
- Every figure the site prints is in `site/facts.json`, with the procedure that reproduces it.

The site is deploy-ready for Vercel and Shadw. The root holds only `index.html` (a redirect), `vercel.json` (output
`site`) and the site folder. The data lives in `data/` and the generator in `_src/`. The design process is recorded in
[`DESIGN-LOG.md`](DESIGN-LOG.md).

The repository before this redesign is on the branch `legacy-2026-10-31`.
